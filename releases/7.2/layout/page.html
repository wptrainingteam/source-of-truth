    The short version

    Overview

    Note: As always, what’s shared here is being actively pursued but doesn’t necessarily mean each will make it into the final release of WordPress 7.2.

    WordPress 7.2 brings a fresh starting point with Ipsum, a minimal new default theme and the first since Twenty Ten that isn’t named after the year. It’s designed as a blank canvas for blogging, with nearly all of its design editable in Global Styles.

    The admin gets a visual refresh, too. The admin bar and admin menu replace the Dashicons icon font with SVG icons drawn in the same style as the block editor’s. It’s one of the most visible changes in the release, and the new icons are also more reliable for screen readers and high-contrast modes.

    Much of this release fills in gaps. Dozens of Core blocks pick up design tools they were missing, from backgrounds and shadows to minimum widths and duotone. Responsive styles and interactive states from 7.1 reach more controls, and Global Styles can now style form elements, custom duotone palettes, and Navigation Link states.

    Collaboration inside the editor keeps improving. Notes move into a margin beside the canvas, where they stay visible while you work, and you can expand, minimize, or hide them. You can react to a note with a small set of emoji instead of writing a reply.

    Beyond that, writing in the editor gets smoother with a long list of small fixes. Image processing in the browser, which arrived in the block editor in 7.1, now extends to uploads in the Media Library and the editor’s media modal, meaning fewer timeouts and memory errors on large images. Developers get public APIs for responsive controls, Interactivity API additions, and new components.

    WordPress 7.2 is scheduled for release on December 8, 2026.

    01

    Priority Items for WordPress 7.2

    Ipsum, the new default theme

    [all] [theme builder]

    WordPress 7.2 ships with Ipsum, a new default theme and the first since Twenty Ten that isn’t named after the year. It’s an intentionally minimal blog theme built as a blank canvas: headers, heroes, and sidebars are there when you need them and stay out of the way when you just want to write. Style variations restyle the whole page, images included, and every color combination meets WCAG AA contrast.

    Ipsum ships with very little CSS. Most of its design lives in theme.json, so nearly everything is editable in Global Styles, which also makes it a good reference for anyone building block themes.

    Ipsum is bundled with WordPress starting with Beta 2 (r64677). The theme is still being refined, so expect changes during the beta period. You can try Ipsum in Playground or download it from the Ipsum GitHub repository and report issues there.

    Notes add emoji support, UI controls, and usability improvements

    [end user] [site admin] [enterprise]

    Notes now sit in a margin beside the editor canvas instead of floating over it, so you can keep a conversation open while you change block or post settings (#83786, #83852). On narrower screens, threads collapse to the author’s avatar. A new Notes submenu in the Options menu lets you expand, minimize, or hide them (#83768).

    Notes also get emoji reactions, so you can acknowledge feedback without adding another reply. Rather than the full emoji set, reactions come from a small, fixed set: 👍 ➕ ❤️ 🎉 😄 👀 🚀 (#76767, #85565).

    After you add a note to a post, a Note icon appears in the block toolbar, making it quicker to leave notes on other blocks as you work through the post. The icon only shows up once a post has a note, so people writing solo keep a focused toolbar (#84635). Highlights also connect more clearly to the text they’re attached to (#80578).

    A few smaller changes protect your work: deleting a note offers Undo (#83988), and unsent notes and replies are kept when you select another block (#84110).

    TrackingNotes iteration for WordPress 7.2 (#80015)

    Design tools for nearly every Core block

    [theme builder] [site admin] [end user]

    Across Gutenberg 24.1 and 24.2, contributors switched on existing design tools for dozens of Core blocks that didn’t have them yet. There are no new controls to learn, just fewer cases where you need a wrapper Group block or custom CSS to get the look you want. Highlights include:

    • Background image, size, and gradient: Buttons, Columns, Heading, List, Media & Text, Gallery, Tabs, and more (#83203, #83226).
    • Shadow: Paragraph, Heading, List, Buttons, Gallery, Quote, Video, and more (#83926, #83045).
    • Minimum width and height: Heading, Columns, Buttons, Embed, Gallery, and more (#83580, #83895).
    • Link, heading, and button colors: Accordion, Tabs, Quote, Details, Post Template (#83390, #83371).
    • Duotone: Gallery, Video, and Media & Text (#83978, #83979, #83981).
    • Fit text: Post Title, Site Title, Site Tagline, and Poetry (#83036, #82074, #83980).

    The Group block can also set separate horizontal and vertical gaps in flex and grid layouts (#81476).

    Theme builders can set all of these in theme.json under styles.blocks. If your theme styles links inside Accordion, Tabs, or Post Template with custom CSS, check for specificity conflicts with the new has-link-color classes. The full list is in the Gutenberg 24.1 and Gutenberg 24.2 changelogs.

    TrackingBlock supports and design tools (#76525)

    Responsive styles and states, round two

    [theme builder] [plugin author] [site admin]

    Responsive styles and interactive states arrived in WordPress 7.1, and 7.2 extends them. You can now set a block’s position per viewport (#83094) and add custom CSS for a specific state (#83539). The Gallery block’s columns, crop, and aspect ratio can change by screen size, too (#82003, #82233).

    Navigation Link blocks get hover, focus, and active controls in Global Styles (#83451), so you can style menu states across your site without editing theme.json.

    For block developers, the viewport API is now public. Custom blocks can use getStyleForState() and setStyleForState() from @wordpress/block-editor to make their own controls work per viewport (#82741).

    TrackingResponsive style states for blocks, 7.2 tasks (#80388)

    Global Styles: form elements, duotone palettes, and more

    [site admin] [theme builder] [end user]

    Global Styles can now style more of the elements that make up your site. Citations, text inputs, and select dropdowns get typography and color controls (#80852), and themes can style <label> elements through theme.json (#81160). Search, comment, and plugin forms can now match the rest of your design without custom CSS.

    Elements like links, buttons, and headings are now listed alongside blocks in Global Styles (#81645), and element screens preview the state you’re styling, such as hover (#83787).

    You can also create your own duotone palettes in a new Duotone tab instead of relying only on the theme’s (#81605). And when you’re tracking down a stray style, Global Styles can filter the block list to show only the blocks you’ve customized (#81373, #84657).

    02

    Improved Blocks and Block handling

    Core blocks pick up a long list of refinements in 7.2, from sorting galleries to finding links and icons faster.

    Gallery: sorting, a Grid variation, and swipeable lightboxes

    [end user] [site admin]

    Galleries you put together by hand can now be sorted, not just dynamic ones. Pick an option from the Order by control, and the images reorder themselves. If you’ve arranged them yourself, the control shows Custom. The existing Random option, which shuffles images on each page load, now sits in the same dropdown, and the ordering controls for both kinds of gallery live together in the Settings panel (#83438).

    A new Grid variation gives you control over the gallery’s layout that the default version doesn’t offer. The default Gallery uses a fixed flex layout. The Grid variation switches to the editor’s grid layout, so you can resize individual images to span more space and build layouts like a large featured image next to smaller ones. You can switch between the two from the inspector, and your layout settings are kept if you switch back (#81909).

    On phones, swiping between images in a gallery’s lightbox is now animated, so visitors can tell they can swipe through the gallery instead of closing it to see the next image (#79114).

    TrackingWordPress 7.2: Dynamic galleries and media inserter (#81370)

    Navigation: one search for every link

    [site admin] [end user]

    When you add a link to a Navigation block, a single search now covers every kind of content at once and shows each result’s type. Posts and pages are ranked ahead of categories, tags, and media, so the link you most likely want is near the top (#83408, #83652, #83407). The Navigation Link block also has a new name in the editor, with Custom Link as its default variation (#82375).

    In the Site Editor sidebar, you can now edit menu links in a popover straight from List View (#84005), and an empty menu shows an inserter so you can start adding links (#84003). The link popover can also set Open in new tab directly (#83506).

    TrackingImprove Navigation Editing in the Extensible Site Editor Sidebar (#77069)

    Icon block: search by keyword

    [end user] [site admin]

    Searching in the Icon block now matches keywords, not just icon names, so typing “hamburger” finds the Menu icon (#82367, #83884). The block’s icon attribute also supports Block Bindings, so the icon can come from a custom field or other source (#80730).

    General quality of life improvements

    [end user] [site admin]

    • Query LoopThe Categories, Tags, and other taxonomy filters now list existing terms as soon as you open them, so you can browse and pick terms instead of having to remember and type their exact names. Selected terms show as chips you can remove, and a term can’t be both included and excluded (#82583). The “Keyword” filter is also renamed “Search terms,” with help text (#82387).
    • ColumnsThe column count slider is gone. Add columns with a plus button instead (#83262), and transform Columns into a Row (#81802).
    • ButtonThe link popover opens only when you ask for it, not every time you select the block (#30166).
    • Cover and Media & TextA new Media section in the block inspector (#82751, #82593), plus an Add Media button in the Media & Text toolbar (#82420).
    • Video and CoverAutoplay respects the visitor’s reduced-motion preference (#83337, #83452).
    • ListTab indents and Shift+Tab outdents selected list items, including multiple at once (#82411, #82460). The block also supports alignment (#68002).
    • TabsContent in inactive tabs can be found with your browser’s Find feature (#81743).
    • PlaylistEdit metadata for several tracks at once (#81441).

    03

    Editor enhancements

    Beyond blocks, the editing experience itself gets smoother, with fewer paper cuts and better ways to work with media and revisions.

    Fewer paper cuts while writing

    [end user]

    A long-running effort to fix everyday editing annoyances continues. You can now insert a block straight from the parent selector in the block toolbar (#81532), press Enter to select the next block (#63484), and apply formatting across several blocks at once (#58913). Multi-selection works on mobile browsers (#81542), and the in-between inserter shows up on wrapped lines (#83276).

    Keyboard users can press Escape to leave the editor canvas and Enter to go back in (#82314), and non-breaking spaces are now marked while you edit, with a button to replace them (#74040, #84737). You can also drag a multi-selection by grabbing anywhere inside it (#81602).

    Media editor: restore the original image

    [end user] [site admin]

    The media editor modal from 7.1 can now restore an image to its original, uncropped version from the More options menu (#81805). WordPress keeps track of which original an edited image came from to make this possible (#81803).

    Images are also attached to the post when you save it. Unattached images in Image and Gallery blocks get the current post as their parent, which makes the Uploaded to this post filter and dynamic galleries more useful (#81977). This is skipped on sites with attachment pages turned on, and on published posts only newly added images are attached (#84851, #84890).

    TrackingWordPress 7.2 Iteration: Media Editor Modal (#80389)

    Visual revisions polish

    [end user] [site admin]

    Visual revisions now show changes to the post title (#82586), and adjacent inline changes are merged so the differences are easier to read (#80579). The Global Styles revisions screen also moved to the same DataViews layout used elsewhere in the editor (#80856). You can also compare revisions in a code diff view from the Options menu (#80314).

    TrackingVisual Revisions: post-7.0 polish (#79120)

    Clearer error screens

    [all]

    When something breaks in the editor, the error screen now explains what happened in plainer language and includes a button to copy the error details, so it’s easier to report the problem or share it with your developer (#76470, #82496). Debugging details are available right in the error screen (#81642), and the Site Editor no longer falls back to a blank screen when one part fails (#82486).

    04

    Admin / Workflow updates

    On This Day in the Activity widget

    [end user] [site admin]

    The Dashboard’s Activity widget gains a Published On This Day section that lists posts you published on today’s date in previous years. It only appears on days when there’s something to show. To make room, Recent Comments moves out of the Activity widget into its own dashboard widget, which you can rearrange or hide like any other (r64593).

    The section shows up to 10 posts. Developers can change the query with the wp_dashboard_on_this_day_query_args filter.

    TrackingFeature request: On This Day dashboard widget (#65116)

    Random content redirects

    [site admin] [end user] [developer]

    WordPress can now send visitors to a random post. Visiting /random/ redirects to a randomly selected published post, and it also works within categories, tags, authors, and post type archives, like /random/category/news/ (r64402). You can change the random base on the Settings > Permalinks screen, and it’s translated for sites in other languages. If a post or page already uses that slug, the content takes priority.

    Try it on this page

    source-of-truth/7-2/random/

    The feature is on by default. Developers can control which post types are eligible with the new randomable argument in register_post_type(), or turn the feature off with the wp_enable_random_content_redirect filter. After turning it off, flush the rewrite rules.

    TrackingAdd core support for random content redirects (#64498)

    Browser-based image processing comes to the Media Library

    [site admin] [end user] [enterprise]

    Browser-based image processing, which arrived for block editor uploads in 7.1, now also covers the Media Library grid, the Add New Media File screen, and the editor’s media modal (r64588). Your browser creates the image sizes instead of the server, so large uploads are far less likely to fail with timeouts or memory errors. Animated images also keep their animation in their sub-sizes now (r64490).

    It runs in supported browsers only. Other browsers, audio files, and the Customizer and classic editor keep the classic upload flow. Developers can turn it off with the wp_client_side_media_processing_enabled filter.

    Tracking#65661 Ticket title needed

    SVG icons replace Dashicons in the admin

    [all]

    The admin bar and admin menu now use SVG icons instead of the Dashicons icon font (r64583). The icons are rendered with wp_get_icon(), the icon API added in 7.1, and the Dashboard’s At a Glance widget uses them too (r64799). SVG icons are announced more reliably by screen readers, work with forced-colors modes, and don’t break when an icon font is blocked.

    Plugins and custom post types that set a Dashicon for their menu item get the matching SVG icon automatically. If a Dashicon has no replacement, it keeps using the icon font. Developers can look up the replacement with WP_Icons_Registry::get_admin_icon_name_for_dashicon() (r64798). If your plugin styles its admin menu icon, check it against the new markup.

    Read moreReplacing Dashicons in the admin bar and menu (#65089)

    Admin accessibility improvements

    [all]

    A new screen option lets you turn off moving meta boxes, so they stay where they are on edit screens (r64301, #50699). Focus states are also easier to see in high contrast mode (r64823, #45910).

    Two more tickets are on the 7.2 roadmap: removing the separate accessibility mode for widgets (#52399) and adding automated axe-core checks to catch regressions (#66015).

    Application password improvements

    [site admin] [enterprise]

    WordPress now sends an email notification when a new application password is created, so an unexpected one is easier to spot (r63582, #63927). On sites without HTTPS, WordPress also explains more clearly which environment type is required to use application passwords (r64091, #57388).

    Safer handling of default_role values is also on the 7.2 roadmap (#46744).

    Global Styles and theme.json

    Text shadow block support and presets

    Text shadow, added to Global Styles in 7.1, is now a block support with a UI. Paragraph and Heading opt in through supports.typography.textShadow, and themes can define presets in theme.json under settings.typography.textShadowPresets. Core ships two defaults, Light and Strong (#79584).

    Preset slug references fixed

    Since WordPress 5.8, var:preset|… references used the raw slug while the generated CSS custom property used a kebab-cased version, so a slug like n27 silently pointed to the wrong variable. References are now kebab-cased to match (#80583). Slugs that already worked are unaffected.

    Override background-color padding

    Themes can now override the padding WordPress adds to blocks that have a background color (#82024).

    Background-clip block support

    A new background-clip block support controls how far a block’s background extends, including clipping it to the block’s text (#77141, #77142).

    Post editor sidebar moves to DataForm

    The post and page settings sidebar is now built on DataForm, the same form system used for Quick Edit (#85081). PluginDocumentSettingPanel, PluginSidebar, PluginPostStatusInfo, the publish panels, and removeEditorPanel keep working, but PluginPostExcerpt hasn’t been ported and may be removed. If your plugin extends the sidebar, test it now.

    Read moreCall for testing: DataForm editor inspector

    DataViews, DataForm, and the Fields API

    The Fields API gains a server-side registry and REST route (#84078). DataViews adds a time field type (#80830), aspectRatio and mediaFit options for grid previews (#79329, #81604), and isAny and isNone filters for numeric fields (#77942). Core actions, like setting the homepage or posts page, are now registered on the server and live in a new @wordpress/core-actions package (#84660, #84643).

    TrackingDataViews, DataViewsPicker, DataForm, Fields in WordPress 7.2 (#81228)

    Interactivity API

    A new data-wp-html directive renders trusted HTML from the store (#83092). The router also exposes state.navigating and state.initiator so you can react to client-side navigations, replacing the deprecated state.navigation.hasStarted and hasFinished (#83280).

    TrackingInteractivity API for WordPress 7.2 (#83078)

    Block API changes

    • Inner block templates move into registerBlockType() settings. The template and templateInsertUpdatesSelection props on <InnerBlocks> are deprecated (#80027).
    • PHP-only blocks: an attribute with items.enum now gets a token field in the inspector (#83394).
    • InspectorControls’ __experimentalGroup prop is removed; use group (#83171).
    • The empty-state block appender is now a real “ghost” block. CSS or tests that target .block-editor-default-block-appender need updating (#81231).

    Plugin menu items and apiFetch

    PluginMoreMenuItem, PluginSidebarMoreMenuItem, and PluginPreviewMenuItem now render with the new Menu component. The as prop is deprecated and ignored (#81564, #82321).

    apiFetch now resolves an empty 200 response to null instead of rejecting with invalid_json (#79325). It also adds apiFetch.unregister() for removing middleware (#82408) and exposes defaultFetchHandler (#82553).

    Components and icons

    @wordpress/ui adds a large set of components, including Menu, CheckboxControl, RadioGroupControl, SwitchControl, SearchableSelectControl, Calendar, Spinner, Meter, and Progress (#79560, #82213, #83143, #83146, #80979, #81337).

    A few utilities that used to be private are now public: withIgnoreIMEEvents in @wordpress/keycodes, for keyboard handlers that shouldn’t fire while someone is typing with an input method editor (#81343), and a new @wordpress/kebab-case package that matches how PHP generates slugs (#81294).

    Icon collections: private icons and core-admin

    Icon collections can now be marked as not public, so icons can ship with WordPress for use in the admin without showing up in the Icon block (#82634, #83277). A new core-admin collection holds the icons used by the admin interface, including a set of popular icons (#83261, #85072), and the Icon block won’t render non-public icons on the front end (#82774).

    Deprecations and breaking changes

    Test your plugins and themes against these before 7.2 is released. Tick them off as you go; your progress stays in this browser.

    • Icons are stroke-based. Core icons were redrawn as strokes, so setting fill no longer recolors them. Use CSS color instead (#78812, #82754).
    • Deprecated components: Badge (#82379), Divider (#83040), ResponsiveWrapper (#83347), Scrollable (#83273), ZStack (#83344), Elevation (#83269), Animate (#80931), and __experimentalSurface (#80943). The private Menu API is also deprecated in favor of the @wordpress/ui Menu (#82947).
    • Interactivity API: Deprecated behaviors that reached their removal date are gone (#84098).
    • @wordpress/reusable-blocks is now a no-op package (#79186).
    • DataViews: The RichText control moved from DataViews’ private exports to the editor package (#81430).
    • Footnotes: Footnote IDs now start with an fn- prefix. Update any CSS or links that target the old IDs (#82398).
    • Block gap: A block that doesn’t declare blockGap support is now treated as not supporting it (#82401).
    • Cross-origin isolation: The editor no longer adds crossorigin attributes to scripts, styles, audio, and video, which caused fatal errors on Chromium 137+ and broke media served from CDNs. wp_start_cross_origin_isolation_output_buffer() and wp_add_crossorigin_attributes() are deprecated, and the header is now sent by the new wp_send_document_isolation_policy_header() (r64489).

    Secrets API

    WordPress 7.2 adds a Secrets API, which gives plugins a standard, encrypted place to store credentials like API keys, with wp_set_secret(), wp_get_secret(), and wp_delete_secret() (r64337). WP-CLI support is in scope, and an admin UI is planned for a later release.

    Read moreProposal: A Secrets API for WordPress 7.2 (#66187)

    wp_kses() rebuilt on the HTML API

    wp_kses() is being rebuilt on the HTML API instead of regular expressions. Output is normalized, <script> and <style> contents are stripped, and some malformed SVG, MathML, and comments are rejected. The wp_kses_force_legacy_parser filter restores the old behavior if you need it.

    Read moreProgress Report: wp_kses() (#66208)

    Try itwp_kses() new parser tester: compare the old and new output for your own HTML

    AI: embeddings in the PHP AI Client

    WordPress 7.2 adds embedding generation through a new wp_ai_client_embedding() function that follows the same pattern as AI prompts (r64327, #65638). It’s infrastructure only: there’s no indexing or search built in. The bundled PHP AI Client is updated to version 1.5.1 (r65001, #66400).

    NO_BACKSLASH_ESCAPES SQL mode turned off

    WordPress 7.2 turns off the NO_BACKSLASH_ESCAPES SQL mode by default, since it can break WordPress’s escaped queries. Sites that need it can turn it back on with a filter in a db.php drop-in.

    Read moreNO_BACKSLASH_ESCAPES SQL mode is now turned off by default in WordPress 7.2
